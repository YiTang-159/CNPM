DUBCHEF – HƯỚNG DẪN TRUY VẤN SSMS & KIỂM TRA LỖI API
Ngày: 01/11/2026

PHẦN A – XEM CÁC BẢNG KẾT QUẢ TRONG SSMS GIỐNG ẢNH MẪU
1. Mở SQL Server Management Studio (SSMS) hoặc Azure Data Studio.
2. Kết nối đúng SQL Server đang chứa DubchefDB dùng bởi website.
3. File > Open > File > mở CNPM-main/db/queries.sql.
4. Chọn database DubchefDB (file đã có lệnh USE DubchefDB; GO).
5. Nhấn Ctrl+A rồi Execute / F5; chọn tab Results.
6. SSMS sẽ hiện 15 nhóm bảng kết quả độc lập: đơn hàng, doanh thu,
   khách hàng chi tiêu nhiều nhất, lượt QR, video/dự án, đơn hàng theo
   tài khoản, tài khoản, đơn hàng chi tiết, thống kê, video, thuyết minh,
   phụ đề, phản hồi, ngôn ngữ, liên hệ.
7. Nếu một bảng hiện 0 dòng, nghĩa là database này chưa có dữ liệu tương
   ứng. File truy vấn KHÔNG tạo dữ liệu mẫu, KHÔNG ghi dữ liệu mới, KHÔNG
   thay đổi dữ liệu đang có.
8. Nếu xuất hiện ThongBao 'Chưa có bảng...', nghĩa là trên SQL Server đang
   truy vấn chưa tồn tại bảng đó. Bạn cần kiểm tra API khởi động thành công;
   backend mới tạo các bảng bổ sung trong db/04-workflows.sql sau khi kết nối.

PHẦN B – KIỂM TRA ĐÚNG SQL SERVER
- Ảnh của bạn cho thấy SSMS đang kết nối 127.0.0.1,14330.
- File docker-compose.yml trong dự án này cấu hình "1433:1433".
- Đây là 2 cổng host khác nhau; chúng CÓ THỂ trỏ đến 2 SQL Server khác nhau.
- Giữ nguyên cả hai cấu hình hiện có, KHÔNG đổi cổng chỉ để giống hình mẫu.
- Trong VS Code Terminal, ở thư mục CNPM-main, chạy:
    docker compose ps
    docker ps --format "table {{.Names}}\t{{.Ports}}\t{{.Status}}"
  Quan sát cột PORTS của container db đang chạy thực tế.
- Trong SSMS, bạn có thể chạy riêng:
    SELECT @@SERVERNAME AS MayChu, DB_NAME() AS CoSoDuLieu;
  Lưu ý: tên server có thể giống nhau khi ở 2 container, nên đối chiếu thêm
  cổng và dữ liệu thực tế.

PHẦN C – KHẮC PHỤC ERR_EMPTY_RESPONSE TẠI http://localhost:3000/api/health
1. Đây là lỗi phía API/backend hoặc mạng giữa trình duyệt và API,
   KHÔNG phải lỗi cú pháp file queries.sql.
2. Mở Docker Desktop và chờ Docker Engine chạy.
3. Mở VS Code Terminal tại thư mục CNPM-main rồi chạy:
    docker compose ps
    docker compose logs api --tail=100
    docker compose logs db --tail=100
4. Nếu API đang restart/exited, xem dòng ERROR trong logs. Ví dụ:
   - Login failed for user 'sa' -> xác thực SQL sai/mật khẩu volume cũ;
   - ECONNREFUSED, ETIMEOUT -> SQL chưa sẵn sàng/không truy cập được;
   - Invalid object/Invalid column -> cấu trúc DB cũ chưa khớp schema;
   - port is already allocated -> có dịch vụ khác chiếm cổng 3000.
5. Trường hợp container không chạy, dùng:
    docker compose up -d --build
   rồi kiểm tra lại http://localhost:3000/api/health.
6. KHÔNG dùng docker compose down -v (sẽ xóa các volume dữ liệu).
7. Sau khi health trả {"ok":true,"db":true} mới thử đăng ký website.
8. Nếu cần hỗ trợ tiếp, gửi ảnh kết quả docker compose ps và
   docker compose logs api --tail=100 (che mật khẩu/thông tin bí mật).

CÁC FILE TRONG ZIP
- db/queries.sql: file truy vấn mới, chỉ đọc, mở trong SSMS.
- db/02-schema.sql: bảng nền tảng, giữ nguyên.
- db/04-workflows.sql: bổ sung Video, ThuyetMinh, PhuDe, PhanHoi.
- docker-compose.yml và web/.env: giữ nguyên, không sửa kết nối.

email đơn hàng nhập sai. Đây là báo cáo, không phải migration schema.
